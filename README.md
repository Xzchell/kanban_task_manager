# Real-Time Kanban Task Manager SaaS

Распределенная SaaS-платформа для управления спринтами и real-time координации кросс-функциональных команд. Проект представляет собой Production-ready MVP, разработанный по принципу раздельной архитектуры (Decoupled Architecture) с независимым фронтендом и бэкендом.

Ориентирован на использование в условиях жестких временных ограничений (хакатоны, краткосрочные спринты), требующих мгновенной синхронизации состояния без ручного обновления страниц.

## 🚀 Технологический стек

* **Frontend:** React, TypeScript, React Context + Custom Hooks (`useAuth`, `useBoard`), React Router (`useNavigate`).


* **Backend API:** Чистый PHP (ООП, PDO), PHPMailer (SMTP-уведомления).


* **СУБД:** MySQL 8.0+ (с глубокой интеграцией транзакционной бизнес-логики и JSON-агрегации на уровне хранимых процедур и функций).


* **Real-Time Слой:** Node.js, Socket.io (WebSocket-сервер для мгновенного broadcasting событий).



---

## 🛠 Архитектурные особенности

1. **MySQL JSON-Aggregation:** Бэкенд получает от СУБД уже готовый вложенный JSON-объект через оптимизированные встроенные функции (например, `GetBoardDetailsFunction`), что минимизирует сетевые задержки (RTT).


2. **Безопасность сессий:** Авторизация на базе защищенных токенов в HTTP-only и Secure Cookies, исключающая XSS-атаки, с возможностью удаленного сброса параллельных сессий.


3. **Diff Sync & Изоляция данных:** Умное точечное обновление связей в БД (теги, исполнители) и строгая изоляция контекстов рабочих пространств (Multi-tenancy) через архитектурный слой Middleware.


4. **Адаптивный UI:** Поддержка двух графических режимов — современного интерфейса с эффектом матового стекла (Blur/Glassmorphism) и плоского производительного стиля для слабых устройств.

## 💻 Локальное развертывание (Инструкция)

### 📋 Требования к окружению

Перед началом установки убедись, что у тебя развернуты:

* Веб-сервер (Apache/Nginx) с поддержкой **PHP 8.0+**
* **MySQL Server 8.0+**
* **Node.js v16+** & npm

---

### 1. Настройка базы данных (MySQL)

1. Создай новую базу данных в твоей СУБД:
```sql
CREATE DATABASE manager_tasks_bd CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

```


2. Импортируй структуру таблиц (14 связанных таблиц) из дампа проекта.


3. **Важно:** Обязательно импортируй все хранимые процедуры и функции (такие как `GetBoardDetailsFunction`, `CreateBoardFunction`, `add_task`), так как на них завязана критическая часть бизнес-логики приложения.



### 2. Развертывание серверной части (Backend API & WebSockets)

#### Настройка PHP API:

1. Перенеси файлы бэкенда в рабочую директорию твоего веб-сервера.
2. В конфигурационном файле подключения к БД (обычно `db.php` или аналогичном модуле внутри слоя моделей/контроллеров) укажи актуальные доступы:


```php
// Пример параметров конфигурации PDO
$host = 'localhost';
$db   = 'manager_tasks_bd';
$user = 'твой_пользователь';
$pass = 'твой_пароль';

```


3. Для работы модуля почтовых уведомлений укажи валидные данные SMTP-сервера (в коде инициализации PHPMailer).



#### Настройка WebSocket-сервера:

1. Перейди в директорию сокет-сервера (модуль на Node.js):


```bash
cd path/to/backend/websocket-server

```


2. Установи зависимости:
```bash
npm install

```


3. Запусти WebSocket-сервер (по умолчанию работает на порту `3001`):


```bash
node index.js

```



### 3. Развертывание клиентской части (Frontend)

1. Перейди в корневую директорию фронтенд-приложения:


```bash
cd path/to/frontend

```


2. Установи необходимые npm-пакеты:
```bash
npm install

```


3. Настрой URL-адреса для взаимодействия с API и WebSockets в конфигурационных файлах фронтенда (укажи локальный адрес твоего бэкенд API и сокет-сервера `http://localhost:3001`).


4. Запусти приложение в режиме разработки:
```bash
npm start

```


5. Открой в браузере [http://localhost:3000](http://localhost:3000).

## 👥 Ролевая модель проекта

Система автоматически разграничивает права доступа с помощью компонента `BoardPermissions`:

* **Owner (Владелец):** Полный доступ к конфигурации доски, колонок, вех, удалению воркспейса и распределению ролей.


* **Admin (Администратор):** Управление участниками, генерация пригласительных ссылок, создание и изменение задач.


* **User (Участник):** Может создавать новые карточки, а также редактировать и перемещать только *свои* задачи (где он является автором или исполнителем).


* **Spectator (Наблюдатель):** Доступ исключительно на чтение без возможности внесения изменений.
